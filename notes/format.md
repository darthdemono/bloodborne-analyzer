# Bloodborne decrypted save format

What is known, how it was checked, and what is not read yet.

## Files

`<savedata>/1/<CUSA id>/SPRJ0005/` holds `userdata0000` to `userdata0009` (one character each, 1,310,720 bytes) and `userdata0010` (settings, 262,144 bytes), plus `backup0000` / `backup0010` written by the game before each save. On this machine: `~/.local/share/bbport/user/savedata/1/CUSA00900/SPRJ0005/`. A real PS4 save is encrypted and must be decrypted first (Save Wizard, a jailbroken console); bbport and shadPS4 store it decrypted.

An unused slot is all zeros. A character file starts `41 00 00 00`; the next four bytes differ between saves, so only the first four are checked.

## It is a stream, so everything is a distance from an anchor

Only two things sit at fixed absolute offsets: `u32 @ 4` the loaded map, `u32 @ 8` the play time in milliseconds (0:39:50 to 4:02:36 across this machine's snapshots; it goes back when an older save is restored, which `combine.py` reports). Everything else moves, because records earlier in the file change length. The chain, as `layout.py` implements it:

1. **FACE**: the ASCII tag `FACE` (the appearance block), first match after offset `0xF000`.
2. **inventory** = FACE offset - 34028.
3. **username** = inventory - 469 (name is UTF-16LE, up to 16 characters).
4. **aob** = username + 68545, and the 8 bytes there must be `03 00 00 00 05 00 01 00`. That marker is the check: it fails loudly if the anchors do not line up, so a wrong layout is never read silently.
5. **storage** = inventory + 34268; **key items** = username + 32201.

Distances from the username (all u32 little-endian unless noted): level -23, Blood Echoes -19, insight -35; vigor -103, endurance -95, strength -79, skill -71, bloodtinge -63, arcane -55; health -147 / -143 / -139 (current, with buffs, base; a snapshot saved mid-fight shows 652 of 698); stamina -119 / -115 / -111; gender `+35`, voice `+36`, origin `+39` (u8, the id, not named: the id to name table is not read from the game yet); New Game cycle `+68831` (u8). Deaths: u32 at aob + 360.

**Invariant that holds on every real save:** level = vigor + endurance + strength + skill + bloodtinge + arcane - 50.

## Inventory, storage, key items

16-byte records. Inventory 1,983 slots, storage 1,984, key items 128 (the 156 bytes after them are counters, not slots). The second part `0xFFFFFFFF` means empty.

| bytes | meaning |
|---|---|
| 0 | handle |
| 4..8 | first part: id + `0xB0` in the top byte for goods; a handle for armor, weapons, gems |
| 8..12 | second part: the thing itself |
| 12..16 | amount |

Type, from the top byte of the first and second part: goods `0xB0` / `0x40` (id = low 3 bytes); armor second part top byte `0x10` (id = low 3 bytes); weapon first part top byte `0x80`: the second part is the decimal weapon id, `+ 100` per upgrade level, `+ 10000` Uncanny, `+ 20000` Lost; gems and runes first part top byte `0xC0`. On this machine's 8 saves no record falls outside these types, which the test suite asserts.

## Boss flags

One bit (or bits) of one byte at a fixed distance from the aob marker: Cleric Beast `aob + 21714` mask `0x08`, Father Gascoigne `aob + 21727` mask `0x80`, and so on for 22 bosses (`bloodborne/bosses.py`, generated by `tools/gen_bosses.py`). A boss is defeated when every listed flag has all its mask bits set. All 22 read "not defeated" on all of this machine's snapshots: the character has not killed one yet, so this reading is **not yet confirmed against a defeated boss**. The first snapshot taken after Cleric Beast dies is the test.

## Names

Read from the game, not typed: `tools/gamefiles.py names <msg dir> db_bb` decompresses `item.msgbnd.dcx` (DCX with plain zlib `DFLT`, then BND4, then FMG) and writes `db_bb/names.json` for goods (FMG `アイテム名`), weapons (`武器名`) and armor (`防具名`). The FMG ids are the ids in the save: goods 1000 is Blood Vial, weapon 5000000 is Hunter Axe. Three armor ids (900000 to 902000) are placeholder rows the game ships without a name and show as "unnamed armor".

## Sources

The anchor chain and distances were read from two public projects, as documentation only, and then checked against this machine's own saves: `Noxde/Bloodborne-save-editor` (GPL-3.0; `offsets.rs`, `constants.rs`, `bosses.json`) and the ImHex pattern `WerWolv/ImHex-Patterns/patterns/bloodborne_save.hexpat`. No code was copied. The boss table is generated from the published offsets, which are facts about the file format. An earlier, weaker reader (`rakesh37187/BBSaveEditor`) found the character block by a table pattern; the FACE chain replaced it and finds one save that pattern missed.

## Not read yet

Gem and rune effects (40-byte records from file offset 84, effect ids that need the game's tables), equipped gear (60-byte blocks above the inventory), appearance (the 235 bytes after `FACE`), map position, most event flags (lanterns, NPC states, Hunter's Dream), the origin name. `integrity.decodedBytes` in the summary says honestly how much is read.
